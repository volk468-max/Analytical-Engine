# Контроль качества и актуальности

`python scripts/validate_project_knowledge.py` проверяет обязательные файлы/поля,
полные Git SHA, локальные ссылки, pinned sources, статус таблицы против status.json,
ID и наличие карточек, базовые шаблоны секретов/персональных email.

`--online` читает только GitHub API этого репозитория: существование всех PR links,
доступность source commits, report paths/blob SHA, текущие PR state/draft/merged/head
и baseline main. Ошибка API или rate limit — failure, а не успешно выполненная проверка.
Все полные Git SHA в knowledge (включая snapshots) классифицированы в
git-object-types.json и проверяются как commit/tree/blob; SHA256 наборов данных
не смешивается с Git SHA. Новый полный Git SHA требует записи в этом реестре.
Исторический факт отсутствия #14 не проверяется как вечный 404: этот номер может
получить новая работа. Новые ссылки на PR тоже проверяются.

`--base-ref <full SHA>` проверяет сохранность старых research records/cards/source
snapshots и append-only CHANGELOG. Для PR с изменениями вне .github требуется
обновление RESEARCH_INDEX, PROJECT_STATUS, NEXT_STEPS и CHANGELOG. Это принуждает
к review памяти и для задач без нового исследования: записать результат проверки,
обоснование отсутствия нового исследования и актуальные PR/SHA. Семантическую
актуальность редактирование файла само по себе не доказывает.

Workflow запускается на новых/обновлённых PR, включая Draft, через pull_request;
только read permissions, без production credentials, write API, LLM, purchases,
сторонних сервисов и автономной правки. Используется стандартный GitHub Actions
runner и stdlib, новые платные подписки не подключаются. Для обязательного merge
gate владелец может отдельно сделать check обязательным в branch protection;
в этой задаче настройки репозитория не меняются.

Для каждой новой версии исследования добавить Rxx-vN карточку/JSON record с новым
source commit, цель/гипотеза/данные/метод/результат/ограничения/решения/вопросы,
явно указать supersedes в тексте, сохранить прежние версии, обновить status.json
и PROJECT_STATUS согласованно. Добавить запись CHANGELOG и пройти проверки.
Если поменялся только статус merge/draft — обновить mutable snapshot и журнал;
историческую карточку не переписывать.

Human review обязателен для значимых утверждений и соответствия источникам,
различий targets/периодов/капитала, решения владельца, приватности, лицензий и
противоречий в прозе. Regex scan не доказывает отсутствие всех секретов/PII;
CI не доказывает корректность расчётов источника или deployed production state.
Доступ к PR/commit не означает, что алгоритм внедрён. Synthetic tests валидатора
проверяют поломанные SHA/статусы/историю/ссылки, но не прибыльность стратегии.
